### Windows native depth training integration

Native preparation records the aligned, confidence-filtered training depth hashes,
the original archive members and the mapping from training filenames to capture
frame IDs. After successful training-only BA, train_reference --measured-depth
checks this provenance and copies the depth inputs into the private checkpoint.

Synthetic integration on the RTX 4050 used two textured planes, eight training
views, one development and one reserved final view. Real COLMAP and real gsplat:
three Adam steps, 384 splats, 7.3 trainer seconds and 0.05 GiB peak PyTorch
allocated GPU memory. The sealed checkpoint verified. These data exercise
mechanics only. Physical iOS capture quality and the native/Polycam A/B are open.

    $env:NAMMA_TEST_CUDA_NATIVE='1'
    python -m pytest -q -p no:cacheprovider tests/test_native_training.py

Observed: 2 passed in 23.23 s.

Studio can run the experiment from an existing native import. Set
`splat_options.native_baseline` to true in the local project.json. On the run
page, select the coordinate frame and choose **Train private LiDAR baseline**.
The job reads the retained member inventory, verifies training photo/depth
bytes, adjusts the training cameras and seals a checkpoint under run evidence.
The normal splat job status and cancel controls apply. The private checkpoint
has no mesh registration or publication approval.

Integration rerun using a real Studio import and the native job subprocesses:
two tests passed in 36.92 s; three GPU training steps took 10.8 s.

The iOS finish sheet now waits for coverage assessment and requires a reason
before finishing a scan with low coverage. The capture engine records the
reason as a coverage_override event in the session. This Windows workstation
has no Swift compiler, Xcode or connected ARKit device. The app change still
requires a build and on-device verification.

## Native development and final evaluation

Once a native reference has passed bundle adjustment, use the retained
imports and the frozen reference with the same registration CLI:

    $env:PYTHONPATH='src'
    python -m namma.evidence.register_views PRIVATE_NATIVE_IMPORT PRIVATE_REFERENCE PRIVATE_DEV
    tools/splat-env/Scripts/python.exe scripts/splat/render_development.py PRIVATE_RUN/evidence/v1 PRIVATE_DEV PRIVATE_RENDERS
    python scripts/splat/score_registered.py PRIVATE_DEV PRIVATE_RENDERS PRIVATE_SCORES

The private depth report identifies high-confidence same-frame measurements,
reports coverage and agreement in metres, and counts missing predictions
against the 2 cm and 5 cm rates. Final registration requires a frozen
candidate and protocol and consumes a capture split once. The synthetic
integration has exercised native final registration, CUDA rendering, and
depth scoring. The real room final split remains reserved.

The first 159-view real-room adjustment had 11 views below the track
minimum. The updated pairing heuristic proposes 810 training-only revisit
pairs, with at least one for each of the 11 weak cameras. Geometric
verification and the full retriangulation guard still need to pass.

The full reference remained below threshold. A development-only exclusion
diagnostic kept 154 training views and preserved candidate overlaps from
the earlier trial. One camera still had two triangulated tracks, including
after a targeted matching retry. The 153-camera follow-up failed because
the neighboring frame also fell to two tracks. A 152-camera retry excludes
both weak neighbors. Both 21-view held-out blocks are unchanged and the reduced
reference is ineligible for final evaluation. The native integration suite
passed all three tests with the CUDA test enabled.
