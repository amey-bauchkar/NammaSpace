## 0. Ground rules (non-negotiable)

1. **Fidelity first.** Never replace or invent real objects, textures, text or geometry. Every accepted change must be
   supported by captured evidence (photos, LiDAR depth, camera poses) and verified on **untouched final-test photos**.
2. **Sharper ≠ better.** No change is accepted on visual sharpness or a single photometric metric.
3. **Never edit** the mesh used for walking, the navigation grid / IF-04 geometry, POIs, metric scale or the model frame.
   The AFE edits only Gaussian-splat appearance.
4. **Preserve existing functionality.** Every new behaviour is behind a flag that defaults to the current behaviour until
   its acceptance criteria pass. With all new flags off, outputs must be identical to before (golden tests).
5. **No paid AI APIs.** Use only local or free GPUs (RTX 4050 6 GB laptop, Kaggle T4/P100 16 GB).
6. **Licences:** use only permissively licensed code and weights (MIT, Apache-2.0, BSD). Non-commercial / research-only
   models are benchmark-only and never ship.
7. **Privacy:** original photos, depth, evidence bundles and full-precision models must never be published in static sites
   or packages.
8. **Reversibility:** originals are immutable; every refinement is a new version with a ledger and one-step rollback.
9. Do not run destructive git commands. Do not delete user data. Do not modify the frozen hash tests in
   `tests/test_phase8_artifacts_preserved.py`.

## 4. Final architecture [D]: hybrid

Strong evidence-preserving reconstruction, then a gated **Adaptive Fidelity Engine (AFE)** that refines defective
regions using classical evidence-constrained arms **and** pretrained proposal arms (AnchorSplat). Every edit is verified
on independent photos.

```
CAPTURE (Namma Capture app primary; Polycam raw secondary)
  live gate on SAVED stills · coverage map · loop closure
        ▼
INGEST & CAPTURE QA (CPU): per-frame sharpness, blur px, ISO, tracking, depth confidence
  → observability map → PASS / RECAPTURE / INVESTIGATE
        ▼
POSES: ARKit priors → COLMAP bundle adjustment ─► VGGT-1B-Commercial cross-check (diagnostic only)
  final-test views registered AFTER BA with the scene frozen
        ▼
DEPTH: LiDAR + RGB ─► Prompt Depth Anything (full-res metric depth + confidence)
        ▼
RECONSTRUCTION: dense seeds (+mesh fill) → unified gsplat trainer (growth per experiment X2;
  pose/colour tables; PromptDA depth loss; optional blur model) → blocks if large
  → EVIDENCE BUNDLE (private, versioned)
        ▼
AFE (gated, per region, variable crop size)
  detect (residual · LPIPS · DINOv2 · duplicated edges · depth error · splat stats)
  → retrieve evidence → observability → diagnose
        ├─ not observed → RECAPTURE (optional labelled "estimated" layer)
        └─ observed → arms:
             classical: P · BL · D0 · D+(PromptDA) · DN · SH · RES · INIT
             pretrained: AI-AS1 · AI-AS20 (AnchorSplat raw, candidates only)
                         AI-INIT (AnchorSplat output → evidence-only regional optimisation)
        → two-store regional optimisation (window-frustum context)
        → VERIFY on untouched final-test photos + hallucination rejection
        → accept (new version + ledger) | reject (discard) | recapture
        ▼
EXPORT: SPZ (bits per experiment X5) · fidelity report · provenance statement · LOD
        ▼
BROWSER: Spark splat (appearance) + mesh (walking, collision, nav, POIs, measure; never edited)
```

**Known AnchorSplat risks [H]:**
- **Degradation mismatch:** it was trained to add detail to low-resolution-trained splats, not to resolve pose ghosting.
  It may sharpen ghost copies or invent a single upright in the wrong place.
- **Scale regime:** a whole room normalised to a unit cube makes offsets ≈ 0.015 × room size (≈ 24 cm for a 16 m lab).
  Region crops are mandatory.
- **20× size explosion:** region-only, subject to budget gates.

## 6. Final corrections (binding)

1. **Variable crop sizes.** AFE regions (including AnchorSplat inputs) are not fixed-size. Choose each region's extent
   from the defect cluster's size, plus a context margin (default 0.25 m), clamped to **[0.5 m, 2.5 m]**. The resulting
   normalised offset scale (0.015 × region extent) must stay within a configurable tolerance of AnchorSplat's training
   regime: default extent ≤ 2 m, i.e. offsets ≤ 3 cm. Large defects are tiled into several regions with frozen
   boundary bands. Record the crop size in the ledger. Crop size is an experimental variable: test at least
   {0.75, 1.5, 2.5} m.
2. **Explicit hallucination rejection.** A candidate (any arm, especially AI arms) is rejected if any of the following
   holds on final-test photos:
   - new or changed high-frequency structure (edges, texture) in the region that does **not** appear in at least two
     independent real photos at the projected location (edge-support test, 2 px tolerance);
   - geometry moves off high-confidence measured depth beyond its noise;
   - an object's projected outline or dimension changes beyond measurement noise;
   - added splats do not project into any real observation (unsupported);
   - per-splat cross-view colour variance increases.

   Rejected candidates are logged as "hallucination". Never silently clipped and kept.
3. **Density-matched controls.** Every arm that changes the splat count (AI-AS20, AI-INIT, DN, INIT) is compared against
   a control with the **same final splat count in the region**: B0-R with densification to the matched count, or
   uniform splitting of the original region splats to the matched count followed by the same regional optimisation
   budget. This prevents "more splats" being credited as "AI restoration".
4. **Untouched final-test observations.**
   - Final-test photos (≥ 10%, from a separate pass or separate area, split by time blocks) are excluded from bundle
     adjustment, seeds, PromptDA prompting, training, AFE detection, strategy selection, crop choice and AnchorSplat
     inputs.
   - They are registered afterwards with the scene frozen (COLMAP `image_registrator`, fixed intrinsics).
   - They are used **once** per milestone; retire after a decision.
   - The development set is used for all iterative choices.

## 7. AFE specification

### A. Detection

Per region, on **dev** photos (never final-test).

| Defect | Signal |
|---|---|
| Blur / missing detail | High-frequency energy ratio (render vs photo); patch LPIPS |
| Ghosting | Duplicated-edge index (autocorrelation of edge maps at 2–30 px offsets); per-splat cross-view colour variance |
| Distortion | Rendered depth vs high-confidence depth (LiDAR or PromptDA) error; splat-to-mesh distance |
| Floaters | Low-opacity splats far from the depth surface; splats seen by < 2 views |
| Elongated splats | Axis ratio > 10:1 and size > 3 cm |
| Colour | Mean bias after the stored colour tables are applied |
| Low density | Splats per projected pixel |
| Semantic mismatch | DINOv2 feature distance render↔photo |
| Poor observation | Observability map |

Map pixel residuals onto splats via alpha-blending weights / gradient magnitude (`means2d` absgrad proxy). Aggregate
into 10–25 cm voxels, cluster into regions, then apply the variable crop sizes (§6.1).

### B. Evidence retrieval

Reuse `splat_blocks.assign_cameras` and add:
- an occlusion test against each view's depth;
- projected resolution (mm per pixel);
- estimated blur px = |angular velocity| × exposure × fx (+ translation term);
- tracking state.

Output per region: photo list with crop windows, depth crops, confidence and quality, tagged train / dev / final-test.

### C. Observability

Initial thresholds, calibrated on the Kitchen:

| Status | Rule | Action |
|---|---|---|
| Sufficient | ≥ 4 sharp views (blur < 1.5 px) at target resolution (≤ 2 mm/px detail surfaces, ≤ 5 mm/px walls), angle spread ≥ 15°, consistent poses | Refine |
| Insufficient | Otherwise | Recapture, no edit |
| Conflicting | Views disagree beyond the scene's photo-to-photo level after pose refinement | Pose/BA first |
| Uncertain geometry | No reliable depth + low parallax | Appearance-only; flag geometry |
| Optimisation-limited | Sufficient evidence, all arms fail | Report "unrecovered under tested methods" |
| Method failure | Crash / divergence / budget exceeded | Revert |

### D. Diagnosis (rule-based)

| Signature | Strategy order |
|---|---|
| Ghosting + high view variance + depth OK | P → INIT → AI-INIT |
| Blur correlated with per-frame blur | BL → RES |
| Depth error / floaters | D+ → INIT → prune |
| Missing detail, high-res evidence | RES → DN → AI-INIT |
| Colour bias | colour tables → SH |
| Low density | DN → AI-INIT |

At most 3 strategies per region per pass. A learned controller is allowed only after ≥ 200 labelled region outcomes
across ≥ 5 scenes and > 30% rule mis-routing.

### E. Two-store regional optimisation

- **Frozen store:** original rows with stable IDs as plain tensors (not `nn.Parameter`). Never given to an optimiser,
  strategy, clamp or regulariser.
- **Trainable store:** region rows plus an inner boundary band (L2-anchored to their originals). The outer band stays
  frozen.
- **Trainable store's own machinery:**
  - fresh Adam per group;
  - its own gsplat `DefaultStrategy` instance with **opacity reset disabled**;
  - prune / split / duplicate confined to the trainable store;
  - new splats rejected if their centre leaves region box + margin;
  - scale clamp and regularisers applied only here.
- **Rendering:**
  - render the concatenation of frozen context subset + trainable store;
  - **fixed SH degree = the model's final degree from step 0**;
  - use the **saved per-camera pose and colour tables**;
  - arm P may adjust region cameras with L2 regularisation toward the stored values;
  - depth loss per the D arms.
- **Merge:** new version = frozen-all minus replaced IDs plus final trainable rows (new IDs). The ledger lists replaced
  and added IDs.
- **Integrity tests:** per-row hashes of frozen rows identical before and after; renders from cameras that cannot see the
  region are pixel-identical.
- **Never** use MCMC inside AFE: its relocation and noise are global.
- **Verify in `tools/splat-env` before relying on them** (gsplat 1.5.3):
  - `DefaultStrategy` internals on a sub-model;
  - `step_pre/post_backward` with renders that include frozen rows (map gradients to trainable rows only);
  - `absgrad` availability;
  - autograd through a partially-trainable concatenation.

### F. Window-frustum context

For each evidence view:
1. Project the region box plus margin into a pixel window W (+8 px).
2. Context = frozen splats whose projected **3-sigma ellipse** (from scale and rotation, as gsplat computes radii)
   intersects W, at any depth: occluders and background included.
3. Supervise only W, using `splat_crops.crop_K`.

**Required equivalence test:** on 100 random views per scene, rendering W with the full scene vs with the context subset
must match within 1e-6 per pixel. Any failure disables culling for that scene. Report measured memory and time; treat
savings as theoretical until measured.

### G. AnchorSplat arms

- **AI-AS1 / AI-AS20:**
  1. Export the region crop (variable size) as an Inria-style PLY in the region's local frame, with
     `NORMALIZATION=bbox`.
  2. Run `inference_external.py` with the matching checkpoint (multiply factor must match: 1 or 20).
  3. Re-import into the world frame.
  4. The result is a **candidate only**: scored, never merged unless it passes all gates (unlikely without AI-INIT).
- **AI-INIT:**
  1. Use the AnchorSplat output as the trainable store's initial state.
  2. Run the same regional optimisation budget as B0-R against the region's train photos, with depth per D+.
  3. Unsupported splats are expected to fade. The hallucination-rejection gates (§6.2) still apply.
- **Controls for AI arms:**
  - **AI-INIT-control:** B0-R from the original region at the same step budget;
  - **density-matched control** (§6.3) at the AI output's splat count;
  - **degradation-matched test:** a well-captured region (Kitchen) deliberately trained at low resolution, where
    AnchorSplat *should* help. It separates "AnchorSplat cannot fix ghosting" from "AnchorSplat does not work on our
    data".

### H. Verification and outcomes

Acceptance gates are in §10. Outcome vocabulary:
- **Verified restoration**: all gates passed on final-test photos.
- **Plausible enhancement**: looks better, not verified; excluded from the faithful model.
- **No improvement.**
- **Inconclusive**: metrics disagree beyond noise; rejected.
- **Hallucination**: §6.2 failed.
- **Insufficient evidence / recapture required.**
- **Unrecovered under tested methods.**

Each attempt is logged in the ledger. Rollback = publish the previous version.

## 10. Quality standards and acceptance gates

**Metrics** (region-masked and scene-level):
- raw PSNR, SSIM, LPIPS; colour-fitted values reported separately and never used for acceptance;
- high-frequency energy ratio; edge F-score (2 px);
- duplicated-edge index; cross-view colour variance;
- depth error vs high-confidence LiDAR / PromptDA (median, % within 2 / 5 cm); completeness;
- splat statistics (opacity, size, needles, floaters);
- integrity (frozen hashes, outside-region pixel equality); boundary-band residual and colour step;
- splat count, SPZ size, peak GPU memory, time;
- viewer median and p95 frame time (RTX 4050 and Intel, 1280×720 and 1920×1080), load time;
- navigation / POI regression suites.

**Accept** a change only if **all** of these hold. Δ = max(2 × B0-R seed spread, minimum detectable effect from S3); no
fixed numbers before S3.

| Requirement | Rule |
|---|---|
| LPIPS | Improves by ≥ Δ |
| Raw PSNR | Not worse than −Δ_PSNR |
| Ghosting | Index not worse (better for ghosting targets) |
| Depth error | Not worse beyond noise |
| Boundary | Not worse |
| Integrity | Exact |
| Hallucination gates | All §6.2 gates pass |
| Density-matched control | Beaten where applicable |
| Splat budget | Region ≤ 2× (20× AI output must be pruned or optimised down) |
| SPZ size | +≤ 10% |
| GPU memory | ≤ 5.5 GB on the 4050 path |
| Viewer frame time | Median +≤ 10% |

Visual review is required, but it is never sufficient on its own.

**Fidelity levels:**

| Level | Capture | Expectation |
|---|---|---|
| F1 | Dense, consistent, native resolution | Readable ≥ ~8 mm text at walking distance |
| F2 | Dense, 1024 px Polycam | Recognisable, soft fine text |
| F3 | Sparse / fast | Medium-distance coherence only; recapture |

**"4K-class"** = detail that survives a 3840 px view because the photos resolved it; it is limited by the source pixel
footprint, not the render size.

## 11. Capture system plan

**Primary tool:** Namma Capture (native app) becomes primary once its archives feed the depth route with ARKit priors +
LiDAR. Polycam raw stays secondary. BA is mandatory for native 12 MP captures.

**App changes** (`ios/NammaCapture`):
- AE/AF lock per sweep (`CameraControls.swift:15`);
- shutter ≤ 1/120 s;
- JPEG ≥ 0.95 or HEIC after a budget test (`CaptureEngine.swift:116`);
- **gate on the saved still** (`CaptureEngine.swift:535-545`, `QualityGate.swift`) using estimated blur px, ISO, luma,
  tracking;
- drop frames whose depth isn't from the same frame, or exclude them from depth (`CaptureEngine.swift:598-650`);
- drop frames near relocalisation (`:665`);
- record exposure, ISO, lens position and angular velocity per frame;
- **new** `ios/NammaCapture/Core/CoverageMap.swift`: live per-surface observability (sharp views, angle spread, mm/px)
  with red/amber guidance; block "finish" until required surfaces pass or the user overrides with a reason.

**Protocols:**
- **All spaces:** lights on; locked AE/AF; ~1 step/s; turns ≤ 30°/s; loop closure; doorways crossed both ways; never
  frame only blank surfaces.

| Space | Passes |
|---|---|
| Small room | Perimeter in, centre out, low and high passes, close passes on objects |
| Large room / lab | Aisle by aisle, two passes per aisle facing 45° to each side, close passes on shelves and desks |
| Corridor | Centre + one per wall at 45° + ceiling/floor pass + 360° at the ends |
| 1BHK | One loop per room from its doorway; hall first |
| Floor | Corridor spine first, rooms anchored to it; sessions ≤ 15 min with shared anchor views |

**Capture QA** (new `src/namma/capture/capture_qa.py`): per-frame metrics plus an observability map; PASS / RECAPTURE /
INVESTIGATE before any GPU job.

## 17. Definition of done

1. Every run writes a private, versioned evidence bundle; published packages include a fidelity report and provenance
   statement and contain no evidence.
2. One unified training route for depth captures, with defaults justified by X2/X3/X5/X6 on ≥ 3 scenes.
3. All quality claims are measured on untouched final-test photos with raw metrics; no fabricated alignment values.
4. The capture app gates on saved stills, guides coverage, and its data is fully consumed.
5. If P5 passed: AFE detects, diagnoses, refines (classical + AI-INIT where proven), rejects hallucinations, keeps every
   version reversible, and reports recapture where evidence is missing.
6. Navigation, POIs, scale, AR walk and the viewer pass their regression suites; frame-time targets are met on the
   reference hardware.

**Realistic limits:**
- No model recovers detail the photos did not resolve.
- AnchorSplat is source-free and, by itself, unverifiable.
- Agreement with the reconstructed mesh is not proof of physical accuracy; validate against tape measures and
  independent photos.
- Some regions will legitimately end as "recapture required".
